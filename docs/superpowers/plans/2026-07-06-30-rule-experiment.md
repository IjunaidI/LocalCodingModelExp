# 30-rule Experiment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a self-contained `experiments/30-rule/` experiment that drives
`Qwen2.5-Coder-3B-Instruct-4bit` (Apple MLX) to emit a `process_calculations(csv_path)`
scoring a full pass on the ~30-rule pricing/commission spec.

**Architecture:** Mirror the `10-rule-v2/` deliverable. A faithful `reference_30.py`
defines ground truth and bakes targets into an input-only CSV; a precise v2-dialect
`spec_30.md` is handed to the model by `solve_30.py` (generate → score → repair);
`prove_30.py` re-scores offline. Ground truth was hand-validated to reproduce Fahad's
`total Receivable` column exactly on rows A/C/F.

**Tech Stack:** Python 3.9, `mlx-lm 0.29.1`, stdlib `csv`/`re`/`argparse`. No pytest —
follow the repo idiom (modules self-check in `__main__`; standalone `prove_*.py` scorers).

## Global Constraints

- Model is fixed: `mlx-community/Qwen2.5-Coder-3B-Instruct-4bit` (the **Coder** variant). Do not swap models.
- Python 3.9 / `mlx-lm 0.29.1`; run everything via `.venv/bin/python` from repo root.
- `TOLERANCE = 0.5` on scored numeric targets; `MAX_TOKENS = 4000` for generation.
- Scored keys: `total_receivables` (primary) and `escrow`. Pass = all rows within tolerance on both.
- Booleans in the Phase-1 dataset are `yes`/`no` text (empty `tax verified` → not verified → withhold).
- Product rate is **derived** from `PRODUCT_RATES[productid][status]` (Rule D); do not feed rate columns.
- Cascade Rules R–AB apply **multiplicatively** `× (1 − rate)` on the running total.
- All new files live under `experiments/30-rule/`; the folder is independently runnable with its own README.
- Ground-truth pipeline order (verified on row C): `adjusted = base_commission × categoryMult`
  → `− 1.5%` risk (P) → `+ 0.25%` referral on post-risk (N) → `+ $5` correction (Q) →
  withholding `3% × (RAD + adjusted + correction)` (O) → `T0 = RAD + adjusted + correction − withholding`.

- [ ] **Step 1: Write the reference with an inline self-check (the failing test first)**

Implement `compute(row)` following the Global Constraints ordering exactly. Key literals:

```python
PRODUCT_RATES = {1: {"individual": 1000, "corporate": 900},
                 2: {"individual": 1500, "corporate": 1200},
                 3: {"individual": 2000, "corporate": 1700}}
CATEGORY_MULTIPLIER = {"electronics": 1.2, "groceries": 0.8, "luxury": 1.5}
ZONE_LOADING = {"domestic": 0.05, "international": 0.08, "cross-border": 0.10}   # Rule H
SPEED_PREMIUM = {"same-day": 0.15, "next-day": 0.10, "standard": 0.0}           # Rule L
QUARTER_LOADING = {"Q1": 0.02, "Q2": 0.0, "Q3": 0.0, "Q4": -0.01}               # Rule G
```

`compute(row)` logic (bare decimals, single-condition operations):

```python
def _yes(v):            # yes/no/empty text booleans; empty -> False
    return str(v).strip().lower() == "yes"

def _num(v, d=0.0):
    try: return float(str(v).strip())
    except (ValueError, AttributeError, TypeError): return d

def _loyalty(years):    # Rule I status from seller years
    if years >= 5: return "platinum", 0.15
    if years >= 2: return "gold", 0.10
    return "none", 0.0

def compute(row):
    g = lambda k: str(row.get(k, "")).strip()
    pid = int(_num(g("productid"), 0)); status = g("status").lower()
    volume = _num(g("volume")); years = _num(g("seller years"))
    rate = PRODUCT_RATES.get(pid, {}).get(status, 0)                 # Rule D
    rbd = volume * rate                                             # receivable before discount
    spring = 0.05 if g("season").lower() == "spring" else 0.0       # Rule A
    vol_tier = (0.05 if volume >= 100 else 0.0) + (0.05 if volume >= 1000 else 0.0)  # Rule B
    strat = 0.05 if g("customer").lower() == "strategic" else 0.0   # Rule C
    loy_status, loy = _loyalty(years)                               # Rule I
    rad = rbd * (1 - (spring + vol_tier + strat + loy))            # receivable after discount
    e = 0.10 * rad if g("region").lower() == "emea" else 0.0        # Rule E
    f = 0.025 * rad if g("payment type").lower() == "credit-card" else 0.0  # Rule F
    gq = QUARTER_LOADING.get(g("quarter").upper(), 0.0) * rad       # Rule G
    h = ZONE_LOADING.get(g("transaction type").lower(), 0.0) * rad  # Rule H
    l = SPEED_PREMIUM.get(g("processing speed").lower(), 0.0) * rad # Rule L
    base_commission = e + f + gq + h + l
    adjusted = base_commission * CATEGORY_MULTIPLIER.get(g("product category").lower(), 1.0)  # Rule J
    if _yes(g("is high risk")): adjusted -= 0.015 * adjusted        # Rule P
    if _yes(g("referral active")) and _num(g("referral invoices remaining")) > 0:
        adjusted += 0.0025 * adjusted                              # Rule N
    correction = 5.0 if _yes(g("requires correction")) else 0.0    # Rule Q
    minfee = 2.50 if (rad + adjusted) < 50 else 0.0                # Rule K (dormant on most)
    pre_wh = rad + adjusted + correction + minfee
    withholding = 0.0 if _yes(g("tax verified")) else 0.03 * pre_wh  # Rule O
    t = pre_wh - withholding                                       # master total (T0)
    pre_cascade_total = t
    # Cascade — all multiplicative on the running total (Rules R,S,T,U,V,X,Y,Z,AA,AB)
    caps = {"karachi", "lahore", "islamabad", "peshawar", "quetta"}
    city = g("city").lower(); cat = g("product category").lower()
    if city in caps: t *= (1 - 0.10)                               # Rule R
    if _yes(g("senior citizen")): t *= (1 - 0.02)                  # Rule S
    if _yes(g("first order")): t *= (1 - 0.05)                     # Rule T
    if cat == "luxury": t *= (1 - 0.04)                            # Rule U
    if _num(g("weight")) > 20: t *= (1 - 0.03)                     # Rule V
    if (g("customer").lower() == "strategic" and loy_status == "platinum"
            and volume >= 1000 and correction == 0.0): t *= (1 - 0.07)  # Rule X
    if (g("season").lower() == "spring" and cat == "luxury"
            and g("processing speed").lower() == "same-day"): t *= (1 - 0.06)  # Rule Y
    if (status == "corporate" and city in caps
            and g("payment type").lower() != "credit-card" and _yes(g("tax verified"))):
        t *= (1 - 0.04)                                            # Rule Z
    if (g("transaction type").lower() == "international"
            and g("customer").lower() == "strategic"
            and not _yes(g("first order")) and volume > 5000): t *= (1 - 0.08)  # Rule AA
    if (loy_status == "platinum" and _yes(g("referral active"))
            and not _yes(g("is high risk")) and _yes(g("tax verified"))): t *= (1 - 0.05)  # Rule AB
    escrow = 0.01 * rbd                                            # Rule M (separate)
    return {"loyalty_status": loy_status, "receivable_before_discount": rbd,
            "receivable_after_discount": rad, "base_commission_total": base_commission,
            "adjusted_commission_total": adjusted, "correction_fee": correction,
            "tax_withholding_amount": withholding, "pre_cascade_total": pre_cascade_total,
            "total_receivables": t, "escrow": escrow}
```

`process_calculations(csv_path)` reads the CSV with `csv.DictReader`, strips header/value
whitespace, calls `compute`, and returns the list of full dicts.

Define `INPUT_COLS` (the 21 input columns from the spec) and `INPUT_ROWS` = the 19 Fahad
rows transcribed from `requirements-source.md` (booleans as `yes`/`no`, rate columns
dropped) followed by **4 synthetic rows** labelled in a comment:
  - S1: `volume > 5000`, international, strategic, not first order, platinum → fires **AA**;
  - S2: tiny order (product 1 individual, `volume` giving `rad + adjusted < 50`, e.g.
    volume 0 won't work → use a row whose discounts/zeroed loadings leave rad+adjusted<50;
    simplest: `volume` small AND all-zero loadings) → fires **K**;
  - S3: all booleans `yes`, corporate, capital city, ach/wire, spring, luxury, same-day,
    platinum, volume ≥ 1000 → fires the **X/Y/Z/AB** cascade;
  - S4: EMEA + credit-card + Q1 + cross-border + next-day, senior + first order,
    heavyweight (`weight > 20`) → fires **E/F/G/H/L + S/T/V** together.

Embed `FAHAD_PRECASCADE` = the 19 `total Receivable` values from Fahad's CSV, then
`[None]*4`.

The `__main__` block writes the CSV and runs the self-check:

```python
if __name__ == "__main__":
    out, targets, escrows = _write_test_cases()          # writes test-cases-30.csv
    check = process_calculations(str(out))
    ok = sum(abs(float(r["total_receivables"]) - t) <= 0.5 for r, t in zip(check, targets))
    print(f"self-check: {ok}/{len(targets)} reproduce their own total_receivables target")
    # Oracle: reference pre-cascade must match Fahad's `total Receivable` on the 19 originals
    rows = [compute(r) for r in INPUT_ROWS]
    matches = 0; mism = []
    for i, (r, fah) in enumerate(zip(rows, FAHAD_PRECASCADE)):
        if fah is None: continue
        if abs(r["pre_cascade_total"] - fah) <= 0.5: matches += 1
        else: mism.append((i, r["pre_cascade_total"], fah))
    print(f"Fahad pre-cascade validation: {matches}/19 match")
    for i, got, exp in mism: print(f"  row {i}: reference {got:.4f} vs Fahad {exp:.4f}")
    assert ok == len(targets), "reference must reproduce its own targets"
```
